# Online room transport and native frames

The development `Room` transport supports a host plus fifteen guests. The normal native lobby/startup still uses the two-player `Session` path. This component has not enabled sixteen-player gameplay or Internet matchmaking in the public demo.

The host assigns connection-bound peer IDs 1..16. Input packets cannot specify a different sender. Host capacity comes from the actual gameplay adapter. Each connection must match nonempty build, content, checkpoint and invitation identities before admission; this transport assumes the shared checkpoint is already installed and does not transfer saves.

The host owns names, unique colors and readiness. Start freezes the accepted roster, closes admission and enters Loading. Each native gameplay adapter must explicitly report completed world loading and actor admission with the same nonzero world token. Only the host can activate the frozen room after every participant reports that token. No input, neutral seed or simulation frame is available beforehand. A mismatched token or startup exceeding 180 seconds stops the room; heartbeats cannot extend this absolute deadline. The token is a caller assertion, not a substitute for implementing native load/admission validation.

A name/readiness edit arriving after Start receives an ordered Locked reply without disconnecting or changing that roster. Guests leaving the lobby free their IDs/colors, invalidate readiness and leave the host available for another guest. Losing a participant during loading or a running match stops the room until a negotiated removal/respawn protocol exists.

Every player submits one command for each consecutive tick. The host waits for the entire frozen roster, then broadcasts the same frame to all participants. Clients validate their own echoed input, including exact floating-point bits. A bounded 64-tick window and byte/packet/queue limits prevent unlimited buffering. Heartbeats and a 15-second running progress deadline stop lost/stalled sessions after activation. A coordinated in-game pause and subsequent level-transition policy is still needed.

Commands contain native interpreted Movement values, a normalized ground-plane view direction, raw controller intent for future action delivery, and an authoritative logical actor incarnation. Raw stick axes cannot substitute for interpreted movement. Source/epoch/basis validation is shared with the native frame coordinator. The current frozen transport epoch is 1; synchronized respawn and epoch changes remain future integration.

`OwnedMovementFrames` maps logical room peers/epochs to separately validated native handles and controller generations. Preflight checks the entire frame before native callbacks. Deliver stages all view bases, then invokes original Mickey Movement handlers exactly once; a partial native failure faults the coordinator and forbids retrying/advancing the world. Finish advances its tick only after the caller completes the native world update. The caller separately publishes the two retail controller lanes. Extra actors currently reject unsupported button/brush/tool intent instead of silently claiming those controls work.

The intended live boundary is after native synchronized join and before original `829ED310` world update. `Room::PeekFrame` allows native preflight without advancing transport consumption. The caller consumes with `TakeFrame` only after successful all-actor admission, then delivers once and finishes after the native tick. The current fixture exercises real TCP room frames through the coordinator and original native action/controller code, with distinct peer view bases, explicit neutral release, and a closed native readiness gate that must retain the exact pending input. Its controlled native continuation sink excludes physical contacts and a complete gameplay world. Normal startup has not been switched to this path.

### Native input production order

The primary application vtable is `8210A0B8`, installed by constructor `829E7DA0`. `8210A0D4` is its interior actions slot, not the table base. The original loop `83075AA0` calls frame virtual+32 (`829EC348`); that frame calls world virtual+48 (`829ED310`) and post-update virtual+52 (`829D95B8`). Inside the world function, `830748B8` calls device refresh virtual+24 and actions virtual+28 (`829E9E30`). The latter dispatches `827C75B0`, which evaluates action math and invokes listeners.

Consequently, current-tick native action callbacks do not exist yet at the existing pre-world network admission boundary. Waiting there for a callback produced later in that same world tick would deadlock. Returning from the middle of the original world update and retrying would repeat earlier services. Native local command production must evaluate the actual selected action math independently before admission, or use an explicitly negotiated delayed-input pipeline. `82767CD8` is a save-manager update, not an input phase, and must not be repurposed.

`online_local_movement.cpp` implements the independent math path for the observed retail Mickey Movement binding. An explicit game-thread lease enables observation at the ordinary Mickey listener entry, after owned-actor quarantine and character-swap suppression. Access revalidates the current registry, resolved player handle, controller/listener, active event context, exact action membership/shape, native profile device selection and device ranges. It rejects stale or unsupported bindings. It does not claim that a missing binding is neutral input.

Production uses the original `827C5990` action math on preserved scratch with a scoped left-axis query. The authored movement records are Y-first (`02400018`, destination0), then X (`02400017`, destination3); response settings remain native. Logical action-player indices and physical input-device indices are resolved separately through the original profile path. No controller cache, native event, camera basis, network tick or wire actor incarnation is manufactured by this helper. It remains unarmed in ordinary gameplay until the Room owner is integrated; actions, Oswald bindings, command view-basis capture and online lifecycle still need that integration.

The canonical executable's regression suite covers sixteen simultaneous TCP connections, all-peer loaded-world activation, a delayed final loader, mismatched/unsolicited world tokens, forged activation, absolute startup timeout, all-peer frame ordering, local echo tampering (including signed zero), missing identities, malformed/spoofed/stale inputs, native-source/basis/epoch validation, Start/profile races, and twenty cumulative lobby leave/rejoins. A separate loopback-to-native fixture binds admitted actors before reporting world readiness and checks received-frame ownership and preflight failure isolation.

Room transport has 493 checks, received-frame/native dispatch has 38, owned movement/reference have 72/11, and the deferred death-event boundary has 14. The local producer has 3,404 checks across 864 native action cases, plus exhaustive left-device conversion comparisons against the original producer/getters. The focused suite runs in the canonical executable with `--em2_test_online_input=true`. These are transport and controlled native fixtures, not a sixteen-player gameplay acceptance test.

A private live check in `tcy_autotopia_visit1.sectiona_first` captured the naturally dispatched retail Movement binding and successfully evaluated five original-math samples: neutral, horizontal, vertical, diagonal, and device deadzone. Controller bytes and caller context stayed unchanged; no samples were dispatched to actors or submitted to the network. It exposed and corrected a real 141-action event list that the initial 128-entry action bound rejected. Action and listener lists now have separate 256/128 bounds with large-list, duplicate and oversized-list checks. Capture: `private-gpu-profile-20261111-083427-d930b3e5`, executable SHA256 `0BB1DC6EEA9899E648428A1A2A032633E1A5DFB45D539A58015953FCE5E24A26`.

Still required: local command production for other binding/actor types, native command view-basis capture, coordinated checkpoint distribution, normal lobby/runtime adoption, all native actor types/actions, actor death/respawn and epoch barriers, full world synchronization, public/invite-only relay matchmaking, Discord invitations, per-instance appearance and overhead names. Direct loopback/LAN TCP tests do not establish router-free Internet play.
