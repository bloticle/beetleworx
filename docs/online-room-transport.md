# Online room transport and native frames

The development `Room` transport supports a host plus fifteen guests. The normal native lobby/startup still uses the two-player `Session` path. This component has not enabled sixteen-player gameplay or Internet matchmaking in the public demo.

The host assigns connection-bound peer IDs 1..16. Input packets cannot specify a different sender. Host capacity comes from the actual gameplay adapter. Each connection must match nonempty build, content, checkpoint and invitation identities before admission; this transport assumes the shared checkpoint is already installed and does not transfer saves.

The host owns names, unique colors and readiness. Start freezes the accepted roster, closes admission and enters Loading. Each native gameplay adapter must explicitly report completed world loading and actor admission with the same nonzero world token. Only the host can activate the frozen room after every participant reports that token. No input, neutral seed or simulation frame is available beforehand. A mismatched token or startup exceeding 180 seconds stops the room; heartbeats cannot extend this absolute deadline. The token is a caller assertion, not a substitute for implementing native load/admission validation.

A name/readiness edit arriving after Start receives an ordered Locked reply without disconnecting or changing that roster. Guests leaving the lobby free their IDs/colors, invalidate readiness and leave the host available for another guest. Losing a participant during loading or a running match stops the room until a negotiated removal/respawn protocol exists.

Every player submits one command for each consecutive tick. The host waits for the entire frozen roster, then broadcasts the same frame to all participants. Clients validate their own echoed input, including exact floating-point bits. A bounded 64-tick window and byte/packet/queue limits prevent unlimited buffering. Heartbeats and a 15-second running progress deadline stop lost/stalled sessions after activation. A coordinated in-game pause and subsequent level-transition policy is still needed.

Commands contain native interpreted Movement values, a normalized ground-plane view direction, raw controller intent for future action delivery, and an authoritative logical actor incarnation. Raw stick axes cannot substitute for interpreted movement. Source/epoch/basis validation is shared with the native frame coordinator. The current frozen transport epoch is 1; synchronized respawn and epoch changes remain future integration.

`OwnedMovementFrames` maps logical room peers/epochs to separately validated native handles and controller generations. Preflight checks the entire frame before native callbacks. Deliver stages all view bases, then invokes original Mickey Movement handlers exactly once; a partial native failure faults the coordinator and forbids retrying/advancing the world. Finish advances its tick only after the caller completes the native world update. The caller separately publishes the two retail controller lanes. Extra actors currently reject unsupported button/brush/tool intent instead of silently claiming those controls work.

The intended live boundary is after native synchronized join and before original `829ED310` world update. The current fixture exercises real TCP room frames through the coordinator and original native action/controller code, with distinct peer view bases and explicit neutral release. Its controlled native continuation sink excludes physical contacts and a complete gameplay world. Normal startup has not been switched to this path.

The canonical executable's regression suite covers sixteen simultaneous TCP connections, all-peer loaded-world activation, a delayed final loader, mismatched/unsolicited world tokens, forged activation, absolute startup timeout, all-peer frame ordering, local echo tampering (including signed zero), missing identities, malformed/spoofed/stale inputs, native-source/basis/epoch validation, Start/profile races, and twenty cumulative lobby leave/rejoins. A separate loopback-to-native fixture binds admitted actors before reporting world readiness and checks received-frame ownership and preflight failure isolation.

The integrated build passes all three CTest suites. Room transport has 461 checks, received-frame/native dispatch has 32, owned movement/reference have 72/11, and the deferred death-event boundary has 14. These are transport and controlled native fixtures, not a sixteen-player gameplay acceptance test.

Still required: native local command production, coordinated checkpoint distribution, normal lobby/runtime adoption, all native actor types/actions, actor death/respawn and epoch barriers, full world synchronization, public/invite-only relay matchmaking, Discord invitations, per-instance appearance and overhead names. Direct loopback/LAN TCP tests do not establish router-free Internet play.
